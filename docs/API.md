# WritingsReader API

Local base URL:

```text
http://localhost:8000
```

Run database migrations before starting the API:

```bash
alembic upgrade head
python main.py
```

Set `DATABASE_URL` and browser origins through the environment when their defaults do not match your setup:

```bash
export DATABASE_URL="postgresql+asyncpg://raffi@localhost/writingsreader"
export ALLOWED_ORIGINS="http://localhost:3000,http://localhost:5173"
```

See [MIGRATIONS.md](./MIGRATIONS.md) for migration details. [`openapi.json`](./openapi.json) contains the generated OpenAPI 3.1 contract.

## Device identity

All writing endpoints require `X-Device-ID`. The API trims the value and accepts at most 128 characters.

```http
X-Device-ID: device-123
```

Missing, blank, and oversized values return `400 Bad Request`:

```json
{
  "detail": "Missing required header: X-Device-ID"
}
```

## Publish a writing

```http
POST /api/writings
```

The iOS app sends the writing and the local prompt snapshot in one request. Publishing does not require a seeded backend prompt.

### Request

```bash
curl -X POST "http://localhost:8000/api/writings" \
  -H "Content-Type: application/json" \
  -H "X-Device-ID: device-123" \
  -d '{
    "client_writing_id": "2d249146-eed2-46e7-91b2-66a8562fc23c",
    "title": null,
    "full_text": "The writing content",
    "prompt": {
      "verb": "Reflect",
      "full_text": "Write about a moment when...",
      "emotions": ["hope", "joy"]
    }
  }'
```

| Field | Rules |
| --- | --- |
| `client_writing_id` | Required UUID generated by the client |
| `title` | Optional; surrounding whitespace is removed; blank becomes omitted; maximum 256 characters after normalization |
| `full_text` | Required; must contain non-whitespace content; maximum 50,000 characters; stored without modification |
| `prompt.verb` | Required nonblank string; surrounding whitespace is removed |
| `prompt.full_text` | Required nonblank string; surrounding whitespace is removed |
| `prompt.emotions` | Required nonempty array of nonblank strings |

The API rejects unknown fields with `422 Unprocessable Entity`.

### Emotion normalization

The API trims and lowercases each emotion. It removes duplicates after normalization while preserving the first occurrence.

Input:

```json
[" Hope ", "JOY", "hope"]
```

Stored value:

```json
["hope", "joy"]
```

### Generated titles

When `title` is omitted, `null`, blank, or whitespace-only, the API:

1. Finds the first non-empty line in `full_text`.
2. Trims that line.
3. Limits it to 256 characters.

The API does not modify `full_text`. It uses `"Untitled"` only when no usable line remains, though request validation rejects whitespace-only content before publishing.

### Created response: `201 Created`

```json
{
  "id": "writing-a81fc203b94d4c4491f5726a0dca881e",
  "client_writing_id": "2d249146-eed2-46e7-91b2-66a8562fc23c",
  "title": "The writing content",
  "full_text": "The writing content",
  "author_id": "device-123",
  "prompt": {
    "verb": "Reflect",
    "full_text": "Write about a moment when...",
    "emotions": ["hope", "joy"]
  },
  "status": "published",
  "created_at": "2026-08-18T08:00:00Z",
  "published_at": "2026-08-18T08:00:00Z"
}
```

The backend-generated `id` identifies the stored writing. `client_writing_id` identifies the client's publish operation.

### Idempotent retry: `200 OK`

Repeating the normalized request with the same `X-Device-ID` and `client_writing_id` returns the stored response. The API does not create another row or regenerate timestamps.

Two devices may publish the same `client_writing_id` because idempotency uses the pair `(author_id, client_writing_id)`.

### Conflicting retry: `409 Conflict`

The same device cannot reuse a client ID with different content, title, or prompt data.

```json
{
  "detail": "client_writing_id already exists for this device with different content"
}
```

### Validation failure: `422 Unprocessable Entity`

```json
{
  "detail": "Request validation failed",
  "errors": [
    {
      "type": "uuid_parsing",
      "loc": ["body", "client_writing_id"],
      "msg": "Input should be a valid UUID",
      "input": "not-a-uuid"
    }
  ]
}
```

### Persistence failure: `500 Internal Server Error`

```json
{
  "detail": "Unable to publish writing"
}
```

The response does not expose database details.

## List writings

```http
GET /api/writings
```

```bash
curl "http://localhost:8000/api/writings" \
  -H "X-Device-ID: device-123"
```

### Response: `200 OK`

```json
[
  {
    "id": "writing-a81fc203b94d4c4491f5726a0dca881e",
    "client_writing_id": "2d249146-eed2-46e7-91b2-66a8562fc23c",
    "title": "The writing content",
    "preview_text": "line one\nline two\nline three",
    "author_id": "device-123",
    "prompt": {
      "verb": "Reflect",
      "full_text": "Write about a moment when...",
      "emotions": ["hope", "joy"]
    },
    "status": "published",
    "created_at": "2026-08-18T08:00:00Z",
    "published_at": "2026-08-18T08:00:00Z"
  }
]
```

`preview_text` contains the first three lines of `full_text`. An empty database returns `[]`.

## Get a writing

```http
GET /api/writings/{writing_id}
```

```bash
curl "http://localhost:8000/api/writings/writing-a81fc203b94d4c4491f5726a0dca881e" \
  -H "X-Device-ID: device-123"
```

### Response: `200 OK`

The endpoint returns the same detail shape as the publish endpoint, including the stored prompt snapshot and timestamps.

```json
{
  "id": "writing-a81fc203b94d4c4491f5726a0dca881e",
  "client_writing_id": "2d249146-eed2-46e7-91b2-66a8562fc23c",
  "title": "The writing content",
  "full_text": "The writing content",
  "author_id": "device-123",
  "prompt": {
    "verb": "Reflect",
    "full_text": "Write about a moment when...",
    "emotions": ["hope", "joy"]
  },
  "status": "published",
  "created_at": "2026-08-18T08:00:00Z",
  "published_at": "2026-08-18T08:00:00Z"
}
```

### Unknown writing: `404 Not Found`

```json
{
  "detail": "Writing 'writing-unknown' not found"
}
```

## Censor text

```http
POST /api/censor
```

This endpoint does not require `X-Device-ID`.

```bash
curl -X POST "http://localhost:8000/api/censor" \
  -H "Content-Type: application/json" \
  -d '{"text": "This is a damn test."}'
```

```json
{
  "text": "This is a **** test.",
  "was_censored": true
}
```

The `text` field must contain non-whitespace text and cannot exceed 50,000 characters.
